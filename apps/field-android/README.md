# Sunpride Field Android

Kotlin/Jetpack Compose native field app. Implemented: invited-employee sign-in, Keystore-encrypted Better Auth session, in-memory Convex JWT, a non-exportable Keystore P-256 device key, admin-registered device lookup and a one-time bind, plus a visit-only encrypted local store. Sync (bootstrap/pull/push) is not wired yet; `device/RequestSigner.kt` is ready for it. The debug build includes a Design tokens preview.

## Auth and device binding (issues #44, #45)

- **Sign-in:** `POST {CONVEX_SITE_URL}/api/auth/sign-in/email` `{email,password}` with **no Origin header**. The session token comes from the `set-auth-token` response header. 400/401 → "Incorrect email or password"; 403 → refused; 429 → rate limited; IO failure → offline; other codes → server error. The password is never stored or logged. The password field is plain `remember`, so it stays out of saved instance state.
- **Session at rest:** `auth/SessionVault.kt` encrypts the session with an AES-256-GCM AndroidKeyStore key (fresh IV per write, fixed AAD). Only IV and ciphertext go to `SharedPreferences`. If the ciphertext fails to decrypt (tamper, lost key, restore onto another device), the app treats it as signed out and wipes it. `allowBackup=false`, and the backup and data-extraction rules exclude all app data. EncryptedSharedPreferences (deprecated) is not used.
- **Convex JWT:** `GET /api/auth/convex/token` with the session bearer. The JWT is held in memory only and refreshed 60 s before its `exp`. A Convex function 401 triggers exactly one refresh and retry. A 401/403 on the token exchange ends the session.
- **Sign-out:** `POST /api/auth/sign-out` with the session bearer (best effort). The local session, JWT and cached deviceId are always wiped. The device key is kept because it is the admin-registered key.
- **Device key:** `device/KeystoreDeviceSigner.kt` uses EC P-256, `PURPOSE_SIGN`, SHA-256. It is StrongBox-backed when `FEATURE_STRONGBOX_KEYSTORE` is present, otherwise TEE; the emulator reports Software. The protection level appears on the enrollment screen and is sent as unverified `attestation.keyId`. The public key is `publicKey.encoded` (DER SPKI) in base64. `EcdsaEncoding` converts JCA DER to 64-byte P1363 using strict DER parsing (short-form lengths, minimal positive INTEGERs, 0 < r,s < n, no trailing bytes).
- **Enrollment:** `mobile/devices:mine {publicKey, app:"ANDROID"}` → `null` shows "This phone isn't registered yet" with the copyable key, fingerprint and model/OS/app version, a **Check again** button and a 10 s auto-poll. Active and unbound → `challenge` → sign `BIND|deviceId|credentialId|nonce|timestamp` → `bind` → read back via `mine` → "Phone ready". Revoked or suspended → "This phone was removed — ask your admin". The bind timestamp is derived from the challenge's server `expiresAt − 60 s`, so phone clock skew can't break the ±60 s window. The deviceId is persisted (non-secret) and re-verified on every launch.
- **DEV public-key file:** the `devDebug` build writes the **public** key only to `/sdcard/Android/data/com.sunpride.field.dev/files/device-public-key.txt` on first launch, even before sign-in or URL configuration. Pull it with `adb pull` and pass it to `packages/backend/scripts/register_device.ts --public-key-file`.

Tests: JVM (`app/src/test`) covers MockWebServer sign-in/token/sign-out/401-retry, Convex envelopes, the enrollment state machine, redaction, and DER↔P1363 plus signer checks against `packages/domain-contracts/fixtures/mobile-v1/crypto/request-proof.json`, which is read in place through a test-resources `srcDir` rather than copied. Instrumented (`app/src/androidTest`) covers Keystore key persistence and sign/verify, StrongBox when the device has it, the encrypted vault round-trip, tamper handling and wipe, and the Compose sign-in/enrollment states.

## Visit-only local store (issue #46)

`storage/FieldStore.kt` exposes `EncryptedFieldDatabase.open(context)` and `RoomFieldStore(db, StoreScope(fullAuthSubject, registeredDeviceId, scopeFingerprint))`. The caller must construct `StoreScope` from an authenticated/bound identity, never from an arbitrary UI selection. SQLCipher for Android **4.12.0**, Room **2.7.2**, AndroidX SQLite **2.7.0** are pinned in `gradle/libs.versions.toml`; `SupportOpenHelperFactory` is mandatory. A random 32-byte install passphrase (ASCII-hex encoded for SQLCipher) is AES-256-GCM wrapped with an independent Android Keystore key; only IV+ciphertext are saved in private preferences. A missing/corrupt key does not fall back to plaintext or erase the database. The app manifest disables backup; both `backup_rules.xml` and `data_extraction_rules.xml` exclude the entire database, file and shared-preference domains (cloud and device transfer). The v1 Room schema is exported under `app/schemas`; do not use destructive migration fallback. `MigrationTestHelper` validates the v1 baseline; add explicit, non-destructive migrations and fixture tests when v2 is introduced.

The repository surface for slices I/K is deliberately small:

- `stage(ScopedSnapshot)` stages a complete assembled bootstrap (employee, route, planned visits, outlets, linked customers, tasks) in a new generation; `swap(generation, finalCursor, leaseExpiresAt, cacheExpiresAt)` atomically promotes it and discards only old **snapshot** rows. Never call swap on a nonfinal page. Readers `todaysVisits(ManilaDay)` and `outlets()` see only the active generation. There is no catalog, price, order, collection or stock cache; server visit/activity deltas are a later slice.
- `enqueue(IntentRow, now)` transactionally inserts an immutable exact serialized visit operation and ordered outbox row; request IDs and client visit IDs are stable UUIDs supplied by the sync layer. `pending()` returns those original bytes in createdAt/requestId order. `recordAck` inserts the server ack **before** marking done in one transaction; `recordRejection` freezes an item for review without destroying its intent. No implicit retry of review items. Duplicate IDs abort rather than mutate a payload.
- `cursor()`/`setCursor(null)` retain pending work; `isLeaseValid(now)` requires a promoted snapshot and `now < offlineLeaseExpiresAt`. Expired caches remain readable as stale, but new intents fail. `syncHealth()`/`setSyncHealth()` are persistent metadata. `holdForReview()` is the sign-out/revoke/scope-change hook: clears the cursor, blocks new intents and keeps unsent work; an explicit supervised recovery workflow is still needed. Do not wipe the DB/passphrase from the existing session-vault sign-out path. Revocation while disconnected cannot be detected immediately; never label cached data live.

The store is not yet wired to network bootstrap or UI reads. The live auth backend **does** invoke `EncryptedFieldDatabase.holdExisting` before sign-out and on removed/unregistered device or expired session, preserving unsent work across credential loss. Later slices must bind all store reads to the verified subject/device/scope and implement supervised reconciliation; held partitions cannot be silently reactivated by a bootstrap. Instrumented tests on emulator and phone exercise persistence, ciphertext absence/wrong key, transaction rollback, snapshot swap, ack ordering, isolation, lease, hold and activity recreation. Production offline authority/geofence/lease policy remains provisional pending server/client approval.

## Requirements and run

JDK 21 (Android Studio JBR), Android SDK API 36 and build-tools 36, a Google APIs ARM64 API 36 emulator image, and Gradle wrapper (included). From this directory:

```sh
export JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home'
export ANDROID_HOME="$HOME/Library/Android/sdk"
cp local.properties.example local.properties # replace placeholders with non-secret DEV URLs
./gradlew :app:assembleDevDebug :app:testDevDebugUnitTest :app:connectedDevDebugAndroidTest :app:lintDevDebug
"$ANDROID_HOME/platform-tools/adb" install -r app/build/outputs/apk/dev/debug/app-dev-debug.apk
"$ANDROID_HOME/platform-tools/adb" shell am start -n com.sunpride.field.dev/com.sunpride.field.MainActivity
```

URLs may instead come from `SUNPRIDE_DEV_CONVEX_SITE_URL` and `SUNPRIDE_DEV_CONVEX_URL` environment variables or Gradle properties; staging/prod use the same names with their respective uppercase prefix. Priority: Gradle property, environment, local.properties. Missing/invalid endpoints show a visible configuration error instead of crashing. Only HTTPS `.convex.site`/`.convex.cloud` origins are accepted, except HTTP localhost and emulator `10.0.2.2` for development. Never put credentials or tokens in properties. Flavor IDs are `com.sunpride.field.dev`, `.staging`, `.prod`; each has a labeled launcher name. minSdk 29 (Android 10) avoids obsolete OS/security behavior while covering modern field devices; target/compileSdk 36. Neither the native app nor this directory has a package.json, so Turbo does not treat it as a JS workspace.

## Design and accessibility

Palette follows `packages/ui/docs/DESIGN.md`: red `#EE1C25`, yellow `#FEF200`, success `#2E9D59`, danger `#C8102E`, ink `#18181B`, light canvas `#F5F5F5` and white surface. The shared CSS `index.css` has a slightly different `#FAFAFA` canvas; the design specification's light `#F5F5F5` is used. Dark canvas/surface are `#060606`/`#181818`. Brand red is retained as a swatch; light primary text/actions use a darker `#AB151C` for WCAG normal-text contrast. Status is labeled in text, not color alone. Spacing is multiples of 4 dp; radii are 8/12 dp. The web bundles Mulish Variable but no redistributable native font license was confirmed here, so Android system default is used with scalable sp type.

`ContrastTest` calculates WCAG sRGB ratios and enforces at least 4.5:1 for every text/background pair in the shell and preview, including the disabled button label. Ratios (normal text): light shell 16.25, surface 17.72, status/disabled 4.63, primary 7.17, error 5.88; dark shell 19.75, surface 17.31, status/disabled 12.13, primary 6.39, error 6.26; yellow 15.11, success 5.13, danger 5.73. The saturated brand-red swatch has no overlaid text because neither dark nor light text reaches 4.5:1 there. Compose tests exercise light, dark and 2.0 font scale. The offline store exists, but no bootstrap/sync UI or financial workflow is connected yet.
