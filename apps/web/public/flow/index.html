01 · Big picture

One system, three apps, one database.

Every app talks to the same Sunpride server. The server keeps one database and is the only thing that talks to SAP.

flowchart LR
  subgraph People["People"]
    OFF["Office, managers, admins"]
    AG["Sales agents"]
    VS["Van sellers"]
  end
  subgraph Apps["Apps"]
    WEB["Sunpride Web
(browser / installable)"]
    FLD["Sunpride Field
(Android)"]
    VAN["Sunpride Van Sales
(Android POS + printer)"]
  end
  subgraph Server["Sunpride server"]
    API["Sunpride API
rules, permissions, sync, chat"]
    DB[("Database
customers, items, orders,
stock, visits, messages")]
    JOBS["Background jobs
reminders, reports, SAP queue"]
  end
  SAP[("SAP
prices, credit, stock value,
invoices & accounting")]

  OFF --> WEB
  AG --> FLD
  VS --> VAN
  WEB -- "live" --> API
  FLD -- "sync when online" --> API
  VAN -- "sync when online" --> API
  API <--> DB
  JOBS <--> DB
  JOBS -- "send orders, get masters" --> SAP

  classDef red fill:#fff,stroke:#ee1c25,stroke-width:2px;
  class API,DB red;
  • SAP stays the master for prices, credit, stock value and accounting. Sunpride keeps a copy and sends work back.
  • Phones work offline. They save everything locally and send it when signal returns.
  • Same data everywhere. An order from the field shows on the web as soon as the phone syncs.
  • Today SAP is a test copy. The live SAP connection comes at cutover.

03 · A sales day

From the monthly plan to the daily report.

The plan is made on the web, the work happens on the phones, and the results come back to the managers the same day.

  • Productive call = a planned visit that really happened, with location evidence.
  • Managers see gaps: who hasn't committed a plan, who is late, which calls were missed.
  • Messages run alongside all of this for questions and updates.
04 · Order to SAP

An order's journey.

A phone order is "pending" until the server and SAP accept it. Nothing is final just because the phone printed it.

sequenceDiagram
  autonumber
  participant P as Phone (Field / Van)
  participant S as Sunpride server
  participant D as Database
  participant Q as SAP queue
  participant SAP as SAP
  P->>P: Save order locally (pending)
  P->>S: Sync when online
  S->>S: Check role, area, prices, credit
  S->>D: Save order + stock movement + audit (all or nothing)
  S-->>P: Accepted / held for review
  D->>Q: Add to SAP queue
  Q->>SAP: Send order
  SAP-->>Q: Accepted, invoice / posting number
  Q->>D: Mark posted
  D-->>P: Status update on next sync
  Note over S,SAP: If SAP is down, the queue keeps retrying. Sales don't stop.
05 · Van stock & cash

Every truck's stock and money accounted for.

Stock only moves through one ledger. Each step is a movement from one place to another, so the books always balance.

flowchart LR
  DEP[("Depot / warehouse")] -- "Load" --> TRK[("Truck stock")]
  TRK -- "Sale + receipt" --> CUS["Customer"]
  CUS -- "Return" --> TRK
  TRK -- "Damage" --> DMG[("Damaged")]
  TRK -- "Unload / leftover" --> DEP
  TRK --> CNT["End-of-day count"]
  CNT --> SET{"Settlement
stock + cash match?"}
  SET -- "yes" --> OK["Day closed"]
  SET -- "no" --> VAR["Variance for review"]

  classDef red fill:#fff,stroke:#ee1c25,stroke-width:2px;
  class TRK,SET red;
  • Voids and returns reverse the original movement; nothing is deleted.
  • Receipts from the van printer are local until SAP posts the real invoice.
06 · Offline & sync

Phones keep working with no signal.

Each phone has its own locked local database and an outbox. Sync sends the outbox and pulls what changed.

flowchart LR
  subgraph Phone["Phone"]
    UI["App screens"] --> LDB[("Encrypted local data")]
    UI --> OUT["Outbox
(work waiting to send)"]
  end
  OUT -- "Push: send work" --> SYN["Server sync"]
  SYN -- "Pull: changes for
my role and area" --> LDB
  SYN --> CHK{"Valid and
allowed?"}
  CHK -- "yes" --> ACC["Accepted"]
  CHK -- "no" --> HLD["Held / needs review
shown on the phone"]
  SYN -. "live nudge" .-> WEB["Web pages refresh"]
  • Sending twice is safe. The same work is never saved twice.
  • Lost access clears old data from the phone; it never comes back by itself.
  • Phone sign-in is tied to the device, so a stolen password alone isn't enough.

08 · How changes ship

From an issue to an update on your phone.

Feedback goes into the built-in Issues board. The dev team picks it up, fixes, tests and releases, then asks you to retest.

flowchart LR
  R["Sunpride reporter
files an issue"] --> BL["Backlog"]
  BL --> DEV["Being worked on
dev team"]
  DEV --> TST["Tested by the team
web + real phones"]
  TST --> LIVE["Released
web: right away
phones: new app version"]
  LIVE --> RT["Ready for retest"]
  RT --> Q{"Reporter
confirms?"}
  Q -- "yes" --> DONE["Done"]
  Q -- "no, comment" --> NF["Needs fix"] --> DEV
  DEV -. "question" .-> WAIT["Waiting on Sunpride"] -. "answer" .-> DEV
  LIVE -. "app update" .-> SYS["System message
with download link"]
