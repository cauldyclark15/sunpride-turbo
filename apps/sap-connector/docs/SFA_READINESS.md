# SAP-001 — SFA/van-sales connector readiness audit

## Verdict

**Partial foundation; not ready for SFA or van-sales production posting.** The connector has a poll/publish/ack loop, local durable queue and signed Convex endpoints, but its live OData adapter only reads inventory snapshots and posts generic sales-order/inventory events. The group 11/15 master, pricing, credit, return and van transaction mappings remain unimplemented; SAP interface compatibility is **UNVERIFIED**. [apps/sap-connector/src/service.js:12-67; apps/sap-connector/src/adapters/odata.js:24-68; docs/delivery/SFA_DELIVERY_SEQUENCE.md:226-240,296-306]

## What exists

- **Transport/direction:** A Bun process inside the client network is designed to initiate outbound HTTPS to Convex; it polls SAP, publishes inbound events, polls Convex tasks and posts them to SAP, then acknowledges Convex. Runtime does not enforce an HTTPS scheme for either configured URL. Local HTTP serves health, readiness and metrics. [docs/architecture/SYSTEM.md:3-13; apps/sap-connector/src/service.js:12-67; apps/sap-connector/src/config/index.js:3-12,14-26; apps/sap-connector/src/index.js:24-43]
- **Signing:** Convex requests carry HMAC-SHA256 over `timestamp.body` in hex; the receiver rejects missing/invalid signatures and timestamps outside a five-minute window. There is no nonce/replay registry at the HTTP boundary; event-ID dedup applies to inbound mutation processing, not arbitrary signed requests. [apps/sap-connector/src/convex/client.js:1-25; packages/backend/convex/http.ts:22-59; packages/backend/convex/integration/sap.ts:33-50]
- **Queue:** SQLite WAL stores inbound/outbound tasks, retains completed rows, dedups globally by event ID (`INSERT OR IGNORE`), takes at most 25 due rows per direction, and retries with capped exponential backoff (2 seconds first failure, 5 minutes maximum), dead-lettering locally at 10 failures. Convex independently limits pending tasks to 25, retries failure acknowledgements with a 60-second cap and dead-letters after its own attempt threshold. No replay command or exception-workflow implementation appears in these paths. [apps/sap-connector/src/queue/sqlite.js:5-63; apps/sap-connector/src/service.js:16-61; packages/backend/convex/integration/sap.ts:336-390]
- **OData:** Basic-auth adapter calls only `/InventorySet` (`$top=100`, ascending change time), maps `inventory.snapshot` v1.0, and posts `sales-order.submit` to `/SalesOrderSet` or any `inventory.*` event to `/InventoryMovementSet`; it forwards payload fields and event ID without SAP-specific transformation. No cursor, pagination, CSRF handling, or customer/product/UOM/price/promotion/credit pull exists in this adapter. SAP services, payload shape and idempotent external-event handling are **UNVERIFIED**. [apps/sap-connector/src/adapters/odata.js:1-68]
- **Contracts:** Five draft-2020-12 v1 schemas exist: envelope (accepts `1.0`/`1.1`; master-data, inventory, sales-order, delivery event prefixes), master-data (product/customer/warehouse), inventory quantity, inventory-movement (receipt/issue/adjustment/status), and sales-order submit (PHP). The package root exports four, omitting inventory-movement. Connector runtime does not import/validate them; HTTP validates only selected envelope fields, while Convex handles snapshots and approved movements and marks successful order acknowledgements `sent_to_sap`. [packages/integration-contracts/sap/envelope.schema.json:1-32; packages/integration-contracts/sap/master-data.schema.json:1-15; packages/integration-contracts/sap/inventory.schema.json:1-34; packages/integration-contracts/sap/inventory-movement.schema.json:1-67; packages/integration-contracts/sap/sales-order.schema.json:1-27; packages/integration-contracts/index.js:1-6; apps/sap-connector/src/service.js:1-97; packages/backend/convex/http.ts:68-109; packages/backend/convex/integration/sap.ts:66-66,160-161,391-401]

## Risks and SAP-team questions

- A successful SAP POST followed by failed Convex acknowledgement can repeat the SAP effect; both queues may diverge. Confirm SAP-side dedup on `externalEventId`, duplicate lookup, reversal and retry policy. [apps/sap-connector/src/service.js:40-60; packages/backend/convex/integration/sap.ts:358-390; docs/decisions/ADR-003-OPERATIONAL-INVENTORY-AUTHORITY.md:17-18]
- Fixed first-page inventory polling can miss or replay changes; snapshots must not overwrite operational balances. Confirm delta tokens, stable ordering, deletion signals, cutoff and reconciliation ownership. [apps/sap-connector/src/adapters/odata.js:24-43; packages/backend/convex/integration/sap.ts:106-157; docs/decisions/ADR-003-OPERATIONAL-INVENTORY-AUTHORITY.md:9-11]
- Ask Sunpride: Which SAP product, edition/version and company codes/plants? Which activated OData services/versions and sample payloads cover masters, orders, returns, loads and financial statuses? Does SAP require Basic, OAuth, certificates, CSRF tokens or a gateway, and what are service-account permissions? Where will the connector host sit, which outbound SAP/Convex endpoints, DNS, TLS trust, firewall/proxy and credential rotation apply? All answers **UNVERIFIED**; production acceptance already calls for endpoint, certificate and privilege checks.
