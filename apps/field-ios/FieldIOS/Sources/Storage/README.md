# Encrypted field store (v1)

`EncryptedFieldStore` implements `FieldLocalStore` on `MainActor`. The official **SQLCipher.swift 4.10.0** SPM binary is pinned exactly in `project.yml` (resolved package checked into the generated project). Opening verifies `cipher_version` and decrypts `sqlite_master` before any migration; there is **no SQLite/plaintext fallback**. A random 32-byte raw key is stored via `SecretStore` in Keychain (`AfterFirstUnlockThisDeviceOnly`, non-synchronizable). Missing key with an existing file fails closed. The Application Support `FieldStore` directory, DB and present WAL/SHM files are excluded from backup and assigned complete-until-first-user-authentication protection. Directory protection covers newly created journal files; tests verify backup exclusion and ciphertext bytes. The simulator does not reliably report file-protection attributes even when setting them succeeds; verify on a physical device before a pilot.

## API and authority boundary

Obtain `AppModel.storage(for:)` only with **verified full auth subject**, bound device ID and the bootstrap `scope.fingerprint`. Every row/query is partitioned by all three. `saveSnapshot(_:cursor:leaseExpiresAt:cacheExpiresAt:for:)` accepts an already complete, validated, assembled bootstrap (H owns paging), stages a new generation and swaps it with cursor/lease in a single transaction. It keeps intents, outbox, acks and sync health. `snapshot(for:)`, `todayVisits(_:for:)` and `outlets(for:)` read the active generation. Snapshot contains only employee, planned visits, outlets, linked customers, route and tasks. Product/catalog, price, order, collection and stock storage are deliberately absent.

`enqueue(_:for:now:)` requires a serialized visit operation with UUID request ID and a valid lease; intent bytes and ordered pending outbox entry commit together. Do not regenerate the payload or UUID on retry. `pendingOutbox(for:)` is ordered by durable sequence **and returns no sendable rows while held**; `heldOutbox(for:)` exposes the preserved queued evidence for supervised review. `recordAck(_:for:in:)` inserts the full server ack before marking outbox done in one transaction; `ack(for:in:)` survives restart. `recordRejection(code:for:in:)` freezes rejected work for supervised review, and `reviewOutbox(for:)` exposes the original immutable intent and rejection code (never deletes evidence). `setCursor(nil,for:)` handles rebootstrap without deleting evidence. `leaseExpiry`, `cacheExpiry` and `isLeaseValid(now:for:)` are server-expiry based, with lease expiry exclusive; cached reads remain available but must be labelled stale by the UI. `setSyncHealth`/`syncHealth` persist diagnostic state. `holdForReview` clears the cursor and blocks new intents without deleting evidence. Snapshot promotion never clears a hold. `releaseHeld(_:)` must only be called after an online profile identity, the same bound device and a successful signed bootstrap for that **same scope** have been verified; AppModel uses this narrow method. A different scope, account or phone leaves previous work held; `hasOtherHeldWork` surfaces that state for supervised review. The broad `releaseHeld(subject:deviceId:)` compatibility API remains for existing storage tests, not for the sync flow. Offline relaunch does not release a hold.

Schema `user_version=2`: v1→v2 adds an encrypted revisioned delta projection table without touching intents/outbox/acks; synthetic encrypted v0 `legacy_intents` migrates UUIDs and operation bytes into the intent/outbox pair. Deferred dependent actions are stored as local templates with a stable UUID and sequence, then materialized transactionally into an immutable sendable v1 operation only after the check-in ack supplies a real server `visitId` (see the wire limitation in the app README). Acks commit before marking an outbox row done; rejected/conflicting/unknown results freeze with their original evidence. Migrations, delta+cursor updates, snapshot swaps and intent/ack state transitions use explicit transactions. Test-only failure injection after intent insert exercises rollback.

**Unresolved policy:** offline lease is a server-supplied provisional expiry, not a client-approved duration. Snapshot feed covers Manila today plus near-term visits; route/plan changes and cursor expiry force rebootstrap. Revocation cannot be detected offline. Neither location/geofence defaults nor offline productivity or per-diem decisions belong in this store. Consult `docs/runbooks/NATIVE_FIELD_DEV.md` and the v1 wire schema before H/J integration.
