# Sunpride Field (iOS DEV scaffold)

SwiftUI field app (DEV). Implemented: Better Auth email sign-in (session from `set-auth-token` when present, otherwise the JSON body's top-level `token` as on DEV; no Origin header, cookies ignored, session in Keychain, Convex JWT in memory), device key (Secure Enclave; simulator uses a TEST-ONLY Keychain key), request signer, enrollment, encrypted SQLCipher local store, signed paginated bootstrap, a store-backed Today list, a daily **Route** screen (Today → Today's route: planned stops in MCP order with Next/In progress/Done/To review state, distance from the phone's current fix to the outlet's single verified pin when both exist, customer code, store code and address, and Apple Maps directions by pin or else address; works offline from the saved day), offline **Customers** search and outlet detail (Today → Find a customer: accent/case-insensitive search over only the outlets in the active verified scope partition by name, outlet/customer code, address, Annex C account/buyer and route code; exact codes first, then today's route order. Detail shows the account summary, route and today's stop, planned visits across the downloaded days, day tasks, this phone's recent call history with send state, office sales and orders cached at bootstrap (last order, 4- and 13-week sales, open orders not yet delivered, credit limit; withheld when the account is shared with an outlet outside the person's plan; no receivables feed exists, so unpaid invoices are not shown), and Directions / Call (dialer) / Open, Continue or Unplanned visit — the visit action stays DEBUG-only like the diagnostic visit), and a DEBUG-only diagnostic visit screen with offline check-in/note/check-out, signed foreground push/pull, review queue and cursor recovery. The enrollment pill reports phone binding, not sync freshness. Today separately shows a persistent store-derived outbox/cache status and detail sheet; queued, deferred, held and rejected work cannot display “All synced.” Offline relaunch shows the last verified partition's saved visits only with an existing session, never a live/ready claim.

## Build and test

Requires Xcode 27 and an available iOS 26+ simulator. From the repository root:

```sh
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
bun run native:ios
# Or choose an available simulator UUID and run xcodebuild build/test without CODE_SIGNING_ALLOWED=NO.
```

Unit tests make no network calls (URLProtocol stubs) and bundle shared JSON bootstrap/error/unknown-enum fixtures directly from `packages/domain-contracts/fixtures/mobile-v1/`, plus the frozen crypto vectors under `crypto/`. UI tests drive the real client against a DEBUG-only in-process fake backend selected with `FIELD_STUB_BACKEND=unregistered|registers|revoked|offline` (stub password `correct-horse`; no real account). Simulator builds are ad-hoc signed (`CODE_SIGN_IDENTITY=-`, no team) because the Keychain needs an application-identifier entitlement.

Open `FieldIOS.xcodeproj` and select the shared `FieldIOS-Dev` scheme to run interactively. `project.yml` is the checked-in XcodeGen source; the generated `.xcodeproj` is also checked in, so XcodeGen is **not** required on a clean clone. After changing the project spec, regenerate from this directory with `xcodegen generate` and include the resulting project diff. Targets: `FieldIOS`, `FieldIOSTests`, `FieldIOSUITests`. Debug and Debug-Dev use `Config/Dev.xcconfig`.

`Dev.xcconfig` defaults to non-secret **localhost placeholders** for both URLs, so the shell can be previewed offline. For real DEV, create gitignored `Config/Local.xcconfig` with `CONVEX_SITE_URL = https:/$()/your-deployment.convex.site` and `CONVEX_URL = https:/$()/your-deployment.convex.cloud`. Xcode config uses `$()` to escape `//`. Both are exposed through Info.plist and validated by `AppEnvironment`; empty, malformed or non-HTTPS URLs (except localhost HTTP) produce a visible configuration error, not a crash. Never put credentials in config, build flags, screenshots or source. No signing team is required for simulator builds.

## Design

Native values follow `packages/ui/styles/index.css`, `sunpride.css` and `packages/ui/docs/DESIGN.md`, imported by the web globals stylesheet. Light canvas/surface `#F5F5F5`/`#FFFFFF`, dark `#060606`/`#181818`; ink/snow `#18181B`/`#FCFCFC`; accent red `#EE1C25`, yellow `#FEF200`, success `#2E9D59`, danger `#C8102E`. Spacing is 4-point based; radii 8/12. Web uses Mulish Variable, but this native scaffold uses the iOS system font and Dynamic Type until a licensed font artifact can be included. The debug-only **Design tokens** screen previews semantic states.

WCAG contrast (normal text, computed sRGB): white on brand red is **4.35:1** and white on yellow **1.17:1**, both below 4.5:1; neither is used for small text. Action buttons use white on darkened red `#B4151D` (**6.85:1**), warning status uses ink on yellow (**15.11:1**), success uses ink on green (**5.13:1**), danger uses snow on `#C8102E` (about **5.7:1**). Unit tests enforce >=4.5:1 on every text pair used in the scaffold, including both neutral themes. Yellow and red are not the only status cues: the pill has text and an icon.

## Today dashboard

Today opens with a summary card (Manila date, calls against the position's daily target, productive calls against the productive-% target, planned stores done, sales against the daily sales target, and sync state with the last-sync time), a **Next**/**Now** card for the next outlet or the open call, a link to the daily route screen, and the ordered visit list (MCP sequence, numbered; done/in progress/next/to review). Everything is read from the encrypted store, so it works offline and after a relaunch; offline is always stated first in the sync line. The target comes from the additive optional bootstrap field `dayTarget` (the person's position standard, from the client memo; omitted ⇒ "no target set"), which also carries the position's `productiveCallRule`. A call is a planned store whose End is recorded on this phone (call answer 2: unplanned visits do not count toward the route target). Productive follows the governed server rule (`packages/backend/convex/sfa/productive_call.ts`, mirrored in `TodayDashboard.swift`): any one listed activity recorded in the call, with the truck-seller merchandising exception; the End outcome alone never makes a call productive, so note-only or call-sheet-only calls are nonproductive. **Next** is only a stop the Start guard (plan order, open call) would allow. Sales come from the additive optional bootstrap field `daySales` (today's orders counted like the Daily Sales Report, in centavos, plus the daily sales target), shown with the time of the download; order capture is not on the phone (`orderCaptureEnabled: false`), so the server total is the day's total.

## Offline order drafts (SP-0044, IOS-014)

During an open call (after **Start**, before **End call**) the visit screen has an **Order** card: **New order** opens `OrderDraftScreen`, which searches the account's product setup offline (code, name or barcode; case- and accent-insensitive, so "nicoise" finds "Niçoise"; exact code/barcode first, then prefixes, then setup order) and takes a whole-number quantity (1–99,999) per product in the setup UOM. **Save draft** writes the draft into the SQLCipher table `order_drafts` (schema v4; the v3 → v4 migration only adds that table), partitioned by subject/device/scope like every other row. Saved drafts reopen from the visit for editing or **Discard**; after End call they stay listed read-only ("review comes next"). Drafts are local only: they never enter the outbox and nothing is sent. Review and submission are IOS-015 (SP-0043). Same rules as Android AND-014.

- **Authorized catalog:** the account's server-owned Annex C call-sheet lines from the scoped bootstrap. The nationwide product master is never offered, and `productCatalog` stays empty (the decoder still rejects a non-empty one).
- **Price/UOM rules:** v1 bootstrap sends `priceAvailability: "unavailable"` (no governed price list yet, ADR-008), so a draft records quantities only, with no unit price, amount or total, and stores `priceAvailability: "unavailable"`. The account and line pricing notes are shown as reference only. A quantity is always in the line's setup UOM; no UOM conversion is cached on the phone.
- **Association:** built from the stored check-in and cached snapshot, never typed: client visit and check-in request IDs, planned visit, outlet, service date, customer ID and code, route, and territory (additive optional bootstrap `outlets[].territoryId/territoryCode`, both or neither; older servers omit them and the draft stores null). `OrderDraftRules.validate` re-checks everything inside the store transaction: the call must still be open (non-rejected check-in, no End), products must be in the current setup with the same code/name/UOM and the same catalog revision, identity and `createdAt` cannot change, a submitted draft is frozen, a held partition refuses save and discard, and an expired offline lease refuses save. If the office later removes or changes a product, the editor lists the line under "No longer set up" and drops it on the next save. Drafts are the person's unsent work: sign-out/revocation cache purges keep them encrypted and held, like the outbox.

Tests: `OrderDraftTests` (search, quantity rules, association, relaunch persistence, forged/stale/ended/held/expired refusals, partition isolation, ciphertext, purge, v3 → v4 migration), `BootstrapTests.testOptionalOutletTerritoryBothOrNeither`, and the v2 → v4 chain in `StorageTests`.

## Sync status, background retry and support info

Today shows queued/sending/review/held counts from SQLCipher, the Manila-time last successful sync, cache staleness, day-close access expiry and an NWPathMonitor offline indicator. Unsent work says **Sync before 10 PM**, or **Late · held for review** once its service day closes at 22:00 Asia/Manila; late work is retained and still sent after access is refreshed. Held/needs-review states take precedence. Access until displays the Manila close time. End − Start device time is shown in minutes, including queued offline calls. Tap its status for frozen-operation reasons and supervisor guidance. `Sync now` shares the AppModel single-flight guard with launch, foreground and network-recovery sync; tapping again during a flight does nothing. Rejected/conflicting/unknown responses stay frozen, never auto-merged, retried or deleted. A scope change can leave previous-scope work held, visibly distinct from the active queue.

`BGTaskScheduler` registers `com.sunpride.field.dev.sync-refresh` (`BGAppRefreshTask`, `fetch` mode) before launch and submits a best-effort request when unsent work exists. The handler restores a saved session on cold launch, invokes the same sync, cancels on expiration and reschedules if retryable work remains. A cancelled HTTP batch retains its persisted UUID/payload; any ack already processed is transactionally durable. No GPS is read in the background. **Apple does not guarantee a refresh time** (and a simulator run does not prove the OS will deliver one). On a real device with an authorized test account and queued work, inspect the scheduled task in Xcode's debugger with `e -l objc -- (void)[[BGTaskScheduler sharedScheduler] _simulateLaunchForTaskWithIdentifier:@"com.sunpride.field.dev.sync-refresh"]`; test expiration with `_simulateExpirationForTaskWithIdentifier:`. These private debugger selectors are diagnostic only, not application code. Confirm an ack or retained queue and rescheduling; also verify background execution, protected-file availability and file protection on the physical device.

Support info exposes only version/build, iOS version, a per-install random opaque handle stored in Keychain, queue counts and allowlisted outcome codes. Its copy action runs through `DiagnosticRedactor`; it never includes public key, identity or request content. Bounded breadcrumbs persist only static event codes (50 max) in an app-support file with complete file protection and backup exclusion; `os.Logger` marks event data private. Neither the log nor support export is a substitute for crash reporting or a live DEV proof.

## Live DEV sign-in and enrollment (manual)

1. Create gitignored `apps/field-ios/Config/Local.xcconfig`:
   ```
   CONVEX_SITE_URL = https:/$()/<deployment>.convex.site
   CONVEX_URL = https:/$()/<deployment>.convex.cloud
   ```
   Build and run `FieldIOS-Dev` on the simulator (Xcode, or `bun run native:ios` then `xcrun simctl install/launch booted com.sunpride.field.dev`).
2. Sign in with an invited employee account. The app shows "This phone isn't registered yet", the SPKI public key, fingerprint and model/OS/app version.
3. Tap **Copy public key**. In DEBUG builds this also writes `Documents/device-public-key.txt`:
   ```sh
   KEY_FILE="$(xcrun simctl get_app_container booted com.sunpride.field.dev data)/Documents/device-public-key.txt"
   ```
4. Admin registers it (own admin JWT, file mode 0600 outside the repo):
   `bun run packages/backend/scripts/register_device.ts --admin-jwt-file PATH --profile-id <employee profile ID> --app IOS --public-key-file "$KEY_FILE"`
5. Within 10 s the app finds the device, binds and shows **Phone ready**. Revoke with `--revoke DEVICE_ID --reason decommissioned`; the next check shows "This phone was removed — ask your admin".

The simulator key is a software key stored in the Keychain (key storage line says TEST ONLY); only a physical phone uses the Secure Enclave.

## Live DEV bootstrap check (integration owner only)

1. Use the gitignored `Config/Local.xcconfig` endpoints above; run `bun run native:ios`, install/launch the built `com.sunpride.field.dev` on the simulator, and sign in as the invited employee. If the phone is not already active/bound, use the separate admin registration flow above; do not self-register or use another person's active device. Never log or screenshot credentials, bearer headers, payloads containing personal data, or the public-key export alongside sensitive evidence.
2. Confirm **Phone ready**, then **Today**, Last synced, and either the scoped planned visits for **Manila today** or the explicit empty state. Use an authorized read-only DEV plan/visit query to compare the today's count and outlet IDs without printing personal data. The historical Sep 28–30 demo fixture does not imply visits on Sep 26; check the live Manila date and actual assignment before expecting rows. Verify the device challenge mutation and the site bootstrap HTTP action both succeeded, with final cursor only after all pages; do not copy signed headers into logs.
3. Disconnect networking after a successful bootstrap, kill and relaunch the app. The previously verified account's saved visits must remain visible with **Stale · pending**, the enrollment must not say Ready, and Sync now must be disabled while the phone cannot be verified. Reconnect, tap Check again/Sync now, and check Last synced advances. Sign out; a different account must not see the previous cached rows.

The client intentionally omits `dayFrom` so the server chooses Manila today; it always sends `limit:100` and follows page cursors. Every page is signed with a new challenge; the timestamp uses `challenge.expiresAt - 30_000` as the server-time midpoint of the backend's 60-second challenge lifetime, avoiding handset wall-clock skew. The working `mobile_fake_device.ts` instead uses local `Date.now()`; its live wire route/body/signature is authoritative, but that timestamp choice is less robust for a skewed phone. Current `http_handlers.ts` emits **flat** `code/message/retryable` errors whereas the frozen error fixtures nest these under `error`; the client decodes both, and the gateway currently masks a revoked proof as `401 unauthorized`, so the UI rechecks `devices.mine` before declaring the phone removed. A 401 alone is not revocation evidence. Lease defaults remain provisional server policy; no field pilot claim follows from this simulator test.

## DEV diagnostic visit and offline sync (integration owner only)

1. Use the approved DEV `Config/Local.xcconfig` and an invited seller with a bound, active iOS device. Run `bun run native:ios`, install/launch the debug app on the available iPhone 17 Pro simulator, sign in and wait for **Phone ready** and **Today**. Confirm a _current Manila-day_ planned row or an authorized scoped outlet for an unplanned call. Historical demonstration visits are not guaranteed to be today; do not fabricate a plan or service date.
2. In Simulator **Features → Location**, select a simulated location. Open a Today row → **Visit diagnostic**. For unplanned mode, supply a nonblank reason. The screen is diagnostic, not a geofence/productivity certification.
3. Disconnect the simulator from DEV (e.g. controlled network link/proxy block) **after bootstrap**. Tap **Start** on arrival and grant _When In Use_ permission if available (with approximate location the app asks once for temporary precise location). GPS check-in (IOS-012): the phone listens up to 15 seconds, stops on the first fix the server policy accepts (≤ 50 m accuracy, ≤ 60 s old, not simulated) and otherwise keeps the best one; it sends coordinates, accuracy, fix time, `provider: fused` and `mockSignal`, never a geofence verdict. The screen then shows the accuracy, the distance from the outlet's verified pin (from the bootstrap) and any reason the supervisor will review (weak signal, old fix, simulated location, no verified pin, more than 500 m away, permission off, location off, no signal). The server records the distance and geofence result per fix; outside-radius fixes go to the governed exception flow (`visits/location:decideLocationException`, a different approver). Denial or no fix saves null location for supervisor review and never blocks the call. There is no distance limit. Optionally **Add note**, then select Completed or Nonproductive (the latter requires a reason) and **End call** after the call. Start and End both attempt GPS evidence. Finish the open call before starting another store; planned calls follow MCP sequence (old feeds retain list order). Verify **Queued**; terminate/relaunch offline and verify the queue remains. A sync attempt may fail without clearing the saved cache. Do not uninstall: that destroys local-only evidence.
4. Reconnect, tap **Check again** if the enrollment is unverified, then **Sync now**. Confirm **Accepted** or a specific **Needs review** entry; verify via authorized DEV readback that there is exactly one visit, one check-in and check-out event, and the same server ack for an identical replay. Do not copy signed request bodies, JWTs, location values or personal data into logs/screenshots. A 409 triggers verified rebootstrap; an altered scope leaves the prior outbox held for supervised disposition. Revoked devices cannot sync while online; offline revocation cannot be observed immediately.

**Wire limitation requiring backend agreement before pilot:** v1 `visit.activity`/`visit.checkOut` demand the server's opaque `visitId`, which does not exist while check-in is offline. The backend does **not** resolve a `clientVisitId` or `dependsOn` UUID into `payload.visitId`; the working fake-device script sends check-in first, takes its ack's `entityId`, then builds the dependent operations. The iOS store therefore persists a deferred local action and UUID atomically while offline, materializes its v1 operation exactly once after the check-in ack, and never edits its bytes after first send. This is not an already-complete immutable _wire_ operation at the moment of offline enqueue. Do not claim that stronger contract property without a v2 server alias/dependency feature. `pull.limit:50` is sent despite prose calling it optional, as the schema requires it; unknown statuses freeze rather than become accepted. The server's location and lease policy remain provisional.
