# Inventory ledger semantics: approval summary (SFD-004)

**Approval requested:** adopt ADR-003 and ADR-007. Convex owns warehouse and truck physical stock; SAP owns accounting, financial inventory, closed periods and SAP document IDs. SAP cutoff snapshots inform reconciliation, never replace balances (ADR-003, §§Decision, Reconciliation and cutover; ADR-007, §Decision). Van stock is movement-derived, not a separate POS quantity (blueprint §26).

## Posting contract

- **Locations and availability:** `inventoryLocations` addresses warehouse, production/WIP, truck, in-transit, returns or virtual boundary. Stock status partitions product × location; lots partition tracked goods. Only `available` stock minus hard reservations is sellable (ADR-007, §Decision).
- **On hand:** sum immutable `inventoryLedgerEntries.quantityDeltaBase` by product/location/status and lot. `inventoryBalances` and `inventoryLotBalances` are versioned summaries, never independent stock edits; `availableBase = availableStockBase - reservedBase`. Quantities use scaled `int64` base units, initially 1,000 per case, with exact configured conversions (ADR-003, §Quantity, lot, and availability policy; ADR-006, §Decision; `packages/backend/convex/inventory/posting.ts:127-157,183-305`).
- **Atomic posting:** `postMovement` checks idempotency key plus payload hash and writes movement/lines, exact allocations, signed ledger entries with before/after/version, summaries, command, audit and outbound effect in one mutation. Same payload replays the original result; changed payload rejects. No SAP call or parallel balance write (`packages/backend/convex/inventory/posting.ts:374-714`; ADR-003, §Decision).
- **Movement types:** opening stock is explicit `opening_balance` / `cutover`, with source reference and required lot/manufacture/expiry data, verified against physical count and SAP totals (`inventory/setup.ts:268-413`; ADR-007, §Decision). Additions are `goods_receipt`; reviewed corrections and count variances are `inventory_adjustment`. Count movements use `sourceType: "stock_count"`, a linked count/adjustment, reason and signed variance; zero variance posts none (`inventory/receipts.ts:225-234`; `inventory/adjustments.ts:143-152`; `inventory/counts.ts:163-241`). Issues, transfers, status changes, production and POS use named movement types (`inventory/validators.ts:53-88`). Never edit posted entries: reverse original allocations or require review if impossible (ADR-007, §Decision).
- **Differences:** reconcile SAP observations at a stated cutoff through a reviewed count/adjustment. SAP rejection remains an integration exception, not an automatic physical rollback (ADR-003, §§SAP outage and recovery, Reconciliation and cutover).
