# SAP interface inventory (ARCH-021)

**Status:** Target contract and SAP-team discovery checklist, not a verified SAP integration. **Every SAP-side service, field mapping, response, authentication method and deduplication capability below is UNVERIFIED.** No endpoint named here is asserted to exist. Authority follows ADR-018, ADR-003 and ADR-008. The connector audit is `apps/sap-connector/docs/SFA_READINESS.md` (§§What exists, Delivery gaps, Risks and SAP-team questions); its SAP-002…SAP-015 issue names map to the rows below.

## Common envelope and operating rule

Connector inside the client network initiates outbound Convex requests: poll SAP changes and publish inbound events; poll approved Convex tasks, post to SAP, then acknowledge Convex. Device → Convex → connector → SAP; no synchronous SAP dependency at checkout (blueprint §§43, 46). All inbound records need source system, entity type, SAP ID, source version/sequence, changed time, payload hash, stable event ID and cutoff/cursor. Outbound records need Turbo source ID, movement/order ID, effect event ID as **SAP external idempotency key**, schema version, payload hash, correlation ID, amount/quantity units and original reference for reversal. Replaying same key must return the original SAP result; changed payload with the same key must fail. Acknowledge both SAP technical document key and visible document number, status, timestamp and rejection reason. Persist events and reconciliation evidence (ADR-003, §Identifier and contract ownership; blueprint §45).

**Retry for all rows:** bounded exponential backoff on transient transport/5xx, rate limit or ambiguous timeout; never assign a new effect key. Quarantine invalid schemas, mismatched IDs, unknown UOMs, duplicate-key/different-payload and business rejections for operator review. Never pretend an HTTP success means a financial posting succeeded. SAP-side duplicate lookup and nonretryable error taxonomy require proof before enablement. The existing connector has two independent retry clocks and local dead letters, but no replay/exception workflow (`SFA_READINESS.md`, §§What exists, Delivery gaps SAP-010–012).

**Reconciliation (SAP-012):** at an agreed cutoff join Turbo effect IDs, approvals, movements, SAP key/no., status and amounts/quantities; expose missing, duplicate, rejected, reversed and valuation/stock variances. Assign exception ownership and replay the original effect ID after resolution. This is a report/workflow, not a snapshot correction. Additional procurement/production/accounting events require a separate contracted row before implementation; generic `inventory.*` POST is not sufficient.

## Current implementation versus target

The current adapter only polls `/InventorySet` first page (`$top=100`, no cursor/pagination), publishes `inventory.snapshot`, and forwards generic `sales-order.submit` to `/SalesOrderSet` or `inventory.*` to `/InventoryMovementSet`, without SAP-specific mapping. Those paths are code assumptions, **not confirmed SAP services**. Local SQLite dedups by event ID and dead-letters at ten failures; Convex has its own retry limit. The five draft schemas do not validate runtime payloads, and only selected HTTP envelope fields are checked (`SFA_READINESS.md`, §§What exists, Delivery gaps). SAP-side idempotency, CSRF, auth, activated services and financial document behavior remain **UNVERIFIED**. Do not certify production posting based on a successful generic POST.
