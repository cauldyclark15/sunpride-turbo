# SAP interface inventory (ARCH-021)

**Status:** Target contract and SAP-team discovery checklist, not a verified SAP integration. **Every SAP-side service, field mapping, response, authentication method and deduplication capability below is UNVERIFIED.** No endpoint named here is asserted to exist. Authority follows ADR-018, ADR-003 and ADR-008. Current mediation lives in `apps/api/src/domains/integration`; `docs/spec/sap.md` documents its local mock contracts. The SAP-002…SAP-015 references below remain discovery identifiers, not proof of production access.

## Common envelope and operating rule

Connector inside the client network initiates outbound Bun API requests: poll SAP changes and publish inbound events; poll approved Bun API tasks, post to SAP, then acknowledge Bun API. Device → Bun API → connector → SAP; no synchronous SAP dependency at checkout (blueprint §§43, 46). All inbound records need source system, entity type, SAP ID, source version/sequence, changed time, payload hash, stable event ID and cutoff/cursor. Outbound records need Turbo source ID, movement/order ID, effect event ID as **SAP external idempotency key**, schema version, payload hash, correlation ID, amount/quantity units and original reference for reversal. Replaying same key must return the original SAP result; changed payload with the same key must fail. Acknowledge both SAP technical document key and visible document number, status, timestamp and rejection reason. Persist events and reconciliation evidence (ADR-003, §Identifier and contract ownership; blueprint §45).

**Retry for all rows:** bounded exponential backoff on transient transport/5xx, rate limit or ambiguous timeout; never assign a new effect key. Quarantine invalid schemas, mismatched IDs, unknown UOMs, duplicate-key/different-payload and business rejections for operator review. Never pretend an HTTP success means a financial posting succeeded. SAP-side duplicate lookup and nonretryable error taxonomy require proof before enablement. Current retries and operator review belong to the API integration outbox/console, not an independent connector database.

**Reconciliation (SAP-012):** at an agreed cutoff join Turbo effect IDs, approvals, movements, SAP key/no., status and amounts/quantities; expose missing, duplicate, rejected, reversed and valuation/stock variances. Assign exception ownership and replay the original effect ID after resolution. This is a report/workflow, not a snapshot correction. Additional procurement/production/accounting events require a separate contracted row before implementation; generic `inventory.*` POST is not sufficient.

## Current implementation versus target

The current gateway is `apps/api/src/domains/integration`, using the local `apps/sap-mock` contract service until real SAP access is supplied. Replicas retain provenance and versioned source facts; the durable posting outbox retains stable keys and reviewable failures. Real SAP services, authentication and accounting idempotency remain unverified. See `docs/spec/sap.md`.
