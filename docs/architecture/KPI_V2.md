## Scope, provenance and refresh

Reads call the ORG `scopeUnitIds` hook and intersect URL unit narrowing with its current subtree. Super-admin/analyst retain their platform cross-scope read rule. Sales is restricted to its own person. Historical sales additionally require the stored order creator, source inventory location, and outlet's current persisted owner. Shared accounting-customer links select one deterministic store, never multiply a source line. This is an allocation default, not evidence of which physical store received a shared-account order; a future explicit order-outlet foreign key is preferable.

Every response has the fixed period/compare/scope/freshness/demo header. Device-behind threshold is provisionally 30 minutes. `asOf` is the source-read snapshot instant. Demo provenance is from scoped sample outlet markers or selected sample AR records, not from made-up name matching. Missing phone sync is not proof of no field work.

`enqueueRefresh(ctx,{kind,date,unitId})` is after-commit and coalesces a durable date job. A refresh recomputes source lines, daily grouping tiles and agent/day metrics; retries replace a day's projection rather than add again. Planned-only days are included; cancelled/replaced plans recompute to zero. A nightly 00:30 Manila task queues bounded daily rebuilds. Topic `analytics` notifications are durable/coalesced and throttled to one per five seconds per process/database.

Current source `change_seq` values and current master fingerprints are checked before serving tiles. Changed orders, lines, people, ownership, links, locations or products force live canonical reads until rebuilt. Cached current scope is never trusted after authorization withdrawal. Read transactions use a repeatable snapshot. Performance fixtures are generated with SQL in throwaway lane databases; they are not the SEED lane's real demo and prove neither cloud nor browser/device latency.

## Targets and audit

The parent hierarchy is company → channel → territory → agent. Use explicit parent if present; otherwise sum known children exactly once. A completely unset tree is null, whereas an explicit zero remains zero. An unset child is not silently invented. Regional managers cannot set global company/channel values. Imports validate every row (including duplicate keys and scope) before writing anything. Each revision soft-retires the prior row and appends a retained `analytics_target_events` record with actor, before/after and timestamp. Named target shape and endpoints remain unchanged.

## Integration limitations to retain

- Frozen schema has no canonical cash-remittance, van sold/returned/closing-stock, discounts or receipt-payment facts. Their amounts remain null; cash-variance and van-stock-variance detection cannot manufacture those facts. The stock-count variant is implemented independently.
- Productive-call integration uses the VISITS seam, mocked only in lane tests. A live multi-lane proof is required after integration.
- The existing numeric target schema is extended additively with centavos/month/level/revision fields. Legacy numeric PHP columns are retained; no destructive data conversion.
- AR is account-level, not automatically attributable to every linked outlet. The implemented snapshot feeds are not proof of an SAP financial integration.
- Work-With partial-week standards, detailed inventory observations for ICO, supervisor ownership for every exception, and complete settlement-based exception fixtures need integration review before claiming full owner acceptance. Multi-day time-in-market sums separate person/day spans, not elapsed overnight gaps.
