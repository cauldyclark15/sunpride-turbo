# Role, capability and organizational scope matrix (ARCH-019)

Decision baseline, not a claim that every endpoint enforces it today. Sources: ADR-005, ADR-009, ADR-011; `packages/backend/convex/lib/capabilities.ts:22-78,88-125`; blueprint §§41–42. The memo requires an approved monthly MCP for per-diem entitlement (§II), work-with supervision (§III), and reports/claims (§V). Approval-chain specifics remain **Provisional — pending Client question 5**. Positions such as CDM, DS and KAS are data, never new app roles (ADR-009).

## Scope key

`G` = all Sunpride units, `T` = current assigned unit and descendants, `O` = own records in assigned unit (field execution), `—` = denied. Roles with `T` at national root have national visibility, at regional root regional visibility, at area root area visibility, and at a supervisor's unit only that subtree. A field employee with `sales` gets subtree _read_ but own records for execution; this distinction is a recommended narrowing for writes, not present in `requireCapability`. A supervisor is normally `manager` in their assigned subtree, not a `supervisor` literal. Position, channel and employment type never grant permission. An active profile without an assigned unit gets **no scoped access**, except bootstrap `super_admin` and the explicitly global read-only `analyst` (ADR-005/009). `admin` assigned to national root may manage national data; a regional admin does not inherit national authority. `super_admin` is the only global writer; `analyst` is the only other cross-scope role and is read-only (`lib/capabilities.ts:82-125`).

Each cell combines **the exact role grant in `CAPABILITIES`** with the intended data scope; `O` is a narrower predicate within the role's subtree. The capabilities list does **not** define `inventory.count` or `inventory.adjustment.request` yet. Until granted explicitly, this matrix does not imply access to those endpoints. `super_admin` bypass in code applies even if a future capability omits that role, so additions must explicitly include it in the documented matrix. Blueprint §41 lists possible extra permissions (`van.load`, `collection.create`, price override); they are not current capability keys and are not silently granted here.

## Enforcement rules and current gaps

1. New endpoints call `requireCapability` **and** derive a trusted target unit from the record before authorizing reads/writes. Omitted `targetUnitId` only checks the role (`lib/capabilities.ts:98-125`); it is not a national-data gate. Filter collections by unit before returning rows, enforce own-record and requester/approver separation, and bind each inventory location to an authorized unit. **Provisional — pending client confirmation:** the exact location-to-sales-unit ownership model and any warehouse exception; until mapped, fail closed for scoped inventory access. Root-gated national imports already use `requireNationalScope` (`imports/products.ts`, `imports/openingStock.ts`).
2. `inventory/adjustments.ts` adjustment requests and `inventory/counts.ts` count-session creation/submission are currently only `requireIdentity` gated; approval and posting have legacy role gates. This is the **CVX-015** follow-up: add explicit capabilities, location scope, separation of duties and migration tests before claiming the table covers those operations. Inventory read queries in `inventory/queries.ts` are also identity-only and need scoped filtering.
3. `domains/orders.ts:47-62,65-82,141-155` lists all orders to any authenticated identity, allows order creation by identity and approves with a flat role gate, without checking the order's unit. Migrate list/create/decide to the matrix, canonical customer assignment and target-derived scope; `visits`/`salesAssignments` currently use `authSubject` and text territory rather than unit keys (`schema.ts:1036-1058`).
4. `sfa/positions.ts:10-37` calls `admin.manage` without a target and reads organization-wide positions/standards. Treat shared position catalogs as national master data (root-scope or global admin) or filter a future unit-scoped catalog. `assignPersona` now funnels role/unit/position changes through assignment history; invitation reads/writes without a unit require national scope. Other legacy inventory operations still call `requireRole`/`requireIdentity`; migrate domain by domain, preserving existing behavior until replaced (ADR-005).
5. Implement capability coverage tests for all eight roles, five example levels (national, regional, area, supervisor, field), cross-subtree denial, historical reorg, own-record checks and analyst read-only. The memo's approver and claimant rules stay provisional pending Client question 5; do not infer them from job titles.

## Group-03 backend contract v1 (2026-09)

`lib/capabilities:currentPermissions` returns `{version: 1, role, orgUnitId, scopeUnitIds, capabilities}` from the authenticated active profile and current effective tree. This is a server-derived UI read model, **not** a client authorization token. `org.read` grants all eight roles (analyst globally, other non-root roles in their subtree); `people.read` grants super admin, admin, manager, analyst, viewer. `admin.manage` is the org/person write grant. Roles and granted keys live in `CAPABILITIES`; position titles and channels never confer authority. No independent versioned distribution artifact or native-client adoption has landed, so #105 remains open.

Org/people endpoint inventory (new surfaces only):

| Endpoint                                                             | Gate and server-owned boundary                                                                                                                                                          |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `org/queries:tree`, `org/queries:list`                               | `org.read`; current caller subtree filters even when querying a historical tree; analyst/super admin global. List paginated.                                                            |
| `org/mutations:create`, `reparent`, `edit`, `deactivate`             | `admin.manage` on persisted parent/old unit and destination; changes audited with authenticated actor.                                                                                  |
| `people/queries:list`, `history`                                     | `people.read`; current assignment unit filters rows; unassigned histories super-admin only. List paginated.                                                                             |
| `people/mutations:assign`                                            | `admin.manage` on stored old unit (or national for unassigned) and validated destination; root role immutable.                                                                          |
| `domains/profiles:list`, `listInvitations`, `listAssignableOrgUnits` | Legacy list remains first-100 for web compatibility but is scoped; use paginated `people/queries:list` for complete reads. Invitations national-only; unit picker scoped (bounded 500). |
| `domains/profiles:invite`, `revoke`, `setRole`, `assignPersona`      | National invitation boundary; role/persona changes use one history writer with both old/new unit checks.                                                                                |

`Asia/Manila` is the date-only interpretation constant; storage is UTC epoch milliseconds with half-open `[from,to)`. Org parent moves are prospective; historical attribution uses as-of edges, but current access always uses current subtree. Profiles remain **login records only**: non-login ADP personnel cannot yet be represented without a separate person shell. This is an explicit follow-up, not a fabricated auth subject or payroll record. Team schema, membership intervals and scoped team endpoints are also deferred to the next bounded slice. Employee codes are unique and immutable once assigned.

Remaining #209/#210 release inventory: legacy `domains/orders.ts`, `inventory/{queries,adjustments,counts}.ts`, `sfa/positions.ts`, sales assignments/visits, imports, connector/integration endpoints and other public mutations/queries still need a per-endpoint auth/read-filter/actor audit; the group-03 gates are not whole-repo sign-off. #210's standardized source/device metadata is not yet uniformly present beyond actor/reason/timestamps in the new org/person transitions. The legacy admin workspace still consumes a first-100 person list pending slice-2 pagination UI; the new backend list is paginated. No web component was changed in this slice.
