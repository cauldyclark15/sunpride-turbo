# Audit and execution events — contract and writer inventory

**Status:** contract proposal and source inventory for SFD-009 / QSR-011; **not** certification that every writer emits a normalized event. This document changes no backend writer. Scope: local application decisions, not an external integration event transport. Review all gaps before closing QSR-011.

## Event contract

`executionEvents` is the append-only normalized execution ledger (`schema.ts`, `visits/events.ts`). A row carries `organizationId`, stored `orgUnitId`, `entityType`/`entityId`, typed `kind`, full authenticated `actorSubject` (`issuer|subject`), `actorRole` and `actorOrgUnitId` **at the decision**, `source` (`mobile|web|system`), optional registered `deviceId`, optional `operationKey`/`correlationId`, `occurredAt` (device-origin time when appropriate), authoritative `serverAt`, `schemaVersion`, optional `policyVersion`, and a bounded redacted `summary` (`before`, `after`, `reasonCode`). The writer also appends a scoped `mobileChanges` position in the same transaction. Server time orders receipt; an offline timestamp is evidence, not authority. System/cron events must identify a distinct system actor and source; retries return the original event ID rather than appending again. Corrections/reversals append a linked decision, never edit or delete history.

Taxonomy: currently emitted `visit.checked_in`, `activity.<typed-kind>`, `visit.checked_out`, `location.exception.decided`, `evidence.attached`; future `plan.submitted|returned|approved|activated`, `device.registered|bound|revoked`, `order.created|approved|rejected`, `pos.sale|void|return`, `inventory.adjustment.requested|approved|rejected|reversed`, `inventory.count.started|submitted|approved_and_posted`, `inventory.route.closed`, and `inventory.reconciliation.completed` need explicit producer mapping, not inferred completion from a generic log. Entity and action names are stable codes, not arbitrary notes. `task.complete` and `collection.record` are unsupported mobile operations until domain policy/writers exist.

Administrative mutation audit must capture a **redacted, field-allowlisted** before/after projection and diff, reason code, effective interval, actor/role/unit snapshot, source and correlation key. `coverageAuditEvents` already carries plan before/after/diff and `createdAt`, but not role, source, device or operation key. `auditLogs` carries only subject/action/entity/time/optional free-text details and **is not** the normalized ledger. `inventoryCommands` carries idempotency hash/key, actor and created/committed times and sometimes device, but not role/unit/source snapshot. `integrationEvents` is outbound delivery, **not** actor audit. Do not treat absence of one ledger as evidence that no old audit exists.

Never copy request bodies, arbitrary comments, passwords, bearer/session tokens, nonces, device public/private keys, attestation material, raw GPS/accuracy, mock signals, photos, customer PII, account details, financial references or full approval signatures to general audit, application logs, analytics, errors or sync projections. Prefer safe state/reason _codes_ and opaque entity references; redact existing legacy free-text details at read/export and migrate future writes. Raw coordinates live only in restricted `visitLocationEvidence`, media in `fieldEvidenceFiles`/storage, with independent access and legal hold. A read surface for the normalized ledger must enforce **current** role/unit scope on stored entity and avoid exposing full subjects to clients; no general-purpose public reader is asserted here.

**PROVISIONAL retention, pending client legal/security sign-off:** audit/execution records 12 months online and 7 years archive; raw location 90 days online / 365 days restricted archive. Holds override destruction. Define archive integrity, backup/restore, purge evidence and subject-access/redaction process with counsel before implementing **any deletion job**; none is provided here. No claim that existing storage currently meets these windows.
