# ADR-018: SAP and Turbo source-of-truth boundary

Status: accepted (2026-09-25, JC lead) — provisional items marked inline.

## Context

Clients write operational intent to Convex, never SAP directly (ADR-010; blueprint §§43–46). Convex owns physical stock (ADR-003); Turbo's governed price list bridges the pre-SAP period (ADR-008). SAP service compatibility is unverified (`apps/sap-connector/docs/SFA_READINESS.md`, §§Verdict, Risks and SAP-team questions).

## Decision

A single owner may change an authoritative field. The other system keeps a versioned projection or a linked financial outcome; neither treats a stale snapshot as a command. "SAP → Turbo" means a connector-fed projection, not a direct mobile-to-SAP call. "Turbo → SAP" means an approved, queued effect, not synchronous checkout (blueprint §§43–46).

Device sequence and movement/effect IDs deduplicate; financial rejection enters review, not a local stock rollback.                                    |

For every boundary crossing retain origin ID, source version/sequence, event ID, payload hash, idempotency key, correlation ID and SAP document identifiers when returned (ADR-003, §Identifier and contract ownership). An identical replay returns the prior result; the same key with different content is rejected. Connector outages leave the Convex posting valid and the effect pending, then visible dead-letter after bounded retries. No SAP call runs inside an inventory mutation (ADR-003, §§Decision, SAP outage and recovery).

## Consequences

- Implement field-level ownership and provenance in projections; reconcile import-origin catalogue rows on feed cutover rather than overwriting them (ADR-006).
- Replace caller-supplied order `unitPrice` financial authority with server-side effective-dated resolution before credit/margin decisions (`ADR-008`, §Known gap). Add credit/promotion feeds and explicit exception handling; these are follow-ups, not claims of working SAP integration (`apps/sap-connector/docs/SFA_READINESS.md`, §§Delivery gaps, Risks and SAP-team questions).
- Ship the SAP interface inventory in `docs/architecture/SAP_INTERFACE_INVENTORY.md` as the contract discovery checklist. Do not activate financial posting without SAP-side idempotency proof.
