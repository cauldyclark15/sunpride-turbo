# Local mobile data protection review (QSR-010 / SP-0018)

Acceptance: sensitive cached data, tokens and logs follow platform storage/security policy and are removed on logout/revocation as defined. Policy source: ADR-020 (credentials in Keychain/Keystore, encrypted local database and evidence under a per-install key, no cloud backup, no tokens or pricing in logs; on revocation purge local tokens/cache but never delete the only copy of unsynced evidence) and ADR-019 (sign-in and bootstrap need connectivity, so nothing is lost by purging cache at sign-out).

## What the phone stores and how it is protected

| Data                                                                                                                        | Android (`apps/field-android`)                                                                                   | iOS (`apps/field-ios`)                                                                                             |
| --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Better Auth session token                                                                                                   | AES-256-GCM under a non-exportable Keystore key; only IV+ciphertext in private prefs (`KeystoreSessionVault`)    | Keychain, `AfterFirstUnlockThisDeviceOnly`, not synchronizable                                                     |
| Convex JWT (15 min)                                                                                                         | memory only                                                                                                      | memory only                                                                                                        |
| Cookies / HTTP cache                                                                                                        | OkHttp with no cache; Set-Cookie not retained                                                                    | ephemeral, cookie-less, cache-less `URLSession`                                                                    |
| Device signing key                                                                                                          | Android Keystore (hardware-backed where available), non-exportable                                               | Secure Enclave; simulator-only software key labelled TEST ONLY                                                     |
| Database key                                                                                                                | random 32 bytes wrapped by a separate Keystore AES key (`PassphraseVault`); no plaintext fallback                | random 32 bytes in Keychain (`ThisDeviceOnly`); missing key for an existing DB refuses to open                     |
| Cached server data: plan/visits, outlets, customers, route, employee header, call sheets and prices, deltas, team summaries | SQLCipher Room database, partitioned by auth subject + device + scope                                            | SQLCipher database (WAL also encrypted), same partitioning; file protection `completeUntilFirstUserAuthentication` |
| Unsent work (intents, outbox, acks)                                                                                         | same encrypted database                                                                                          | same encrypted database                                                                                            |
| Visit photos                                                                                                                | AES-256-GCM per file under its own Keystore key, local ID bound as AAD, `noBackupFilesDir`; deleted after upload | not implemented on iOS yet                                                                                         |
| Diagnostics                                                                                                                 | allowlisted codes only, `Log.i` in debug builds only; bounded breadcrumbs in `noBackupFilesDir`                  | allowlisted codes, OSLog dynamic values `.private`, redacted support export, backup-excluded file                  |
| Backup / device transfer                                                                                                    | `allowBackup=false`; backup and data-extraction rules exclude sharedpref, database and file domains              | DB directory and files excluded from backup                                                                        |

## Removal on sign-out and revocation (changed in this issue)

Before SP-0018 both apps only **held** local work on sign-out/revocation: the session and cursor were cleared, but the cached plan, outlet and customer lists, call sheets with prices, employee header and deltas stayed in the encrypted database until the same person bootstrapped again. A different person signing in could not read them (partitioned), but they remained on a phone that was signed out or confirmed lost.

Now:

| Event                                                                                                                   | Android                                                                                                    | iOS                                                                                     |
| ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Sign-out (including session ended)                                                                                      | `EncryptedFieldDatabase.purgeExisting` (every partition), session-keyed scope index cleared, session wiped | `purgeAllCachesForReview` (every partition), Keychain session + partition pointer wiped |
| Confirmed revocation/suspension (`device_revoked`/`scope_changed` from the gateway, `devices.mine` = revoked/suspended) | `purgeExisting` from the controller; `purgeCacheForReview` for the partition in `VisitSync`                | `purgeCacheForReview` for the active partition and in-memory visits/call sheets cleared |
| Unexplained 401, update required, lease expiry, unregistered                                                            | hold only (unchanged): recoverable states keep offline reads                                               | hold only (unchanged)                                                                   |

Purge deletes the server cache tables (snapshots, call sheets/lines, deltas) and clears partition metadata (generation, employee, route, cursor, lease and cache expiry), with `secure_delete` on and a WAL `TRUNCATE` checkpoint so deleted rows are overwritten. It keeps, encrypted and **held**, the intents, outbox, acks and pending photos, so unsynced evidence is never destroyed (ADR-020). A held partition cannot enqueue new work; only a verified bootstrap of the same subject + device + scope releases it, and that bootstrap reloads the cache.

## Not covered / open

- Offline stolen phone: it cannot learn of revocation, so its cache stays until its next server contact (ADR-020 accepts this; MDM wipe is the control). The 24-hour offline lease still stops new work.
- Held unsent evidence of a departed or replaced employee stays encrypted on the phone until a supervised recovery; there is no in-app supervised export/wipe yet.
- Android has no `FLAG_SECURE`, and iOS no app-switcher privacy cover, so the recents thumbnail can show the visible screen (customers, prices). Not required by ADR-020; product decision needed.
- File-protection attributes and Secure Enclave behaviour are only verifiable on a physical iPhone; Android hardware-backed Keystore only on a real phone.
- Server-side session revocation on sign-out is best effort when offline (local wipe always happens).
