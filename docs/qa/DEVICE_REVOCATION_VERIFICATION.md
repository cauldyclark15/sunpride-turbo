# Device revocation and lost-device verification (QSR-007 / SP-0021)

Acceptance: revoked devices lose protected access according to policy while preserving unsynced data handling and auditability (ADR-020). Runbook: [`MOBILE_DEVICE_INCIDENT.md`](../runbooks/MOBILE_DEVICE_INCIDENT.md). Local cache removal on revocation and sign-out: [`MOBILE_LOCAL_DATA_PROTECTION.md`](MOBILE_LOCAL_DATA_PROTECTION.md).

## Policy as implemented

| Status      | Server access                          | How it is set                                                                                       | Reversible                                                                                                 |
| ----------- | -------------------------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `active`    | challenge, bind, bootstrap, pull, push | `devices.register` / `devices.reinstate`                                                            | —                                                                                                          |
| `suspended` | none                                   | `devices.suspend` (lost, stolen, suspected_compromise, other)                                       | yes, `devices.reinstate` (found, other) to the same employee and unit, only while no replacement is active |
| `revoked`   | none                                   | `devices.revoke` (lost, stolen, suspected_compromise, transfer, replacement, decommissioned, other) | never                                                                                                      |

Every status change needs `admin.manage` over the phone's stored unit (and the employee's current unit while active), writes a coded reason (never free text) to the device row and a `device.*` audit entry. Acknowledged operations (`processedMobileOperations`), `mobileSyncState` and audit history are never deleted. The admin console (Administration → Phones) lists in-scope phones and shows, per phone, what the server received, last contact, offline-access expiry and the status history, without key, credential or sign-in subject material.
