# Mobile sync DEV proof (slice F)

This runbook describes a disposable device smoke test, **not** proof that a live DEV bearer was exercised by this change. Never run `convex deploy` or put JWTs, session tokens, private keys, proof signatures, or GPS fixes in argv, logs, or the JSON summary. The CLI reads two short-lived Convex-audience JWTs from private files; obtain them by exchanging authenticated Better Auth sessions at `GET $CONVEX_SITE_URL/api/auth/convex/token` (see `docs/contracts/MOBILE_AUTH_V1.md`). The JWT has a short expiry; renew both shortly before running. Ensure the HTTP action identity propagates into internal authorizer on DEV; unit tests alone cannot establish it.

## Preparation

1. Configure `CONVEX_URL` (`https://…convex.cloud`), `CONVEX_SITE_URL` (`https://…convex.site`), and `TMPDIR` in the runtime environment. The CLI creates a mode-0600 PKCS8 key in `TMPDIR`, deletes it on completion, and never prints its contents. Use a disposable active employee and an admin with `admin.manage` for that employee's current unit. There must not already be an active device on the employee; reconcile any outstanding offline outbox before revoking/replacing one. Supply the employee's **profile ID**, not their subject or email.
2. Save the salesperson and admin's Convex JWTs in separate mode-0600 files outside the repository. Do not pass token contents in flags or shell history. Do not read `.env` files. The admin registers and revokes a temporary iOS device; the salesperson challenges and binds it. The CLI uses ECDSA P-256 SPKI and signs the exact request body SHA-256 digest, nonce and timestamp for each HTTP call.
3. Check the fixture without writes: `bun run packages/backend/scripts/mobile_fake_device.ts --check-fixture --sales-jwt-file /private/sales.jwt --admin-jwt-file /private/admin.jwt --profile-id <PROFILE_ID> --service-date 2026-09-28 --json-out /private/fixture.json`. The check queries the authorized employee's plan list and reports active plan IDs/count. It does not register/challenge/bind/revoke or push. The DEV Demo Sales planned visits are Sep 28–30 Manila, while Sep 26 has none: do not forge a date or seed over the 18-visit plan.
4. On the **actual Manila service day**, provide a verified outlet-pin latitude/longitude from an authorized fixture source using `--lat <LAT> --lng <LNG>` (required; bootstrap v1 does not expose a pin). Run `bun run packages/backend/scripts/mobile_fake_device.ts --sales-jwt-file /private/sales.jwt --admin-jwt-file /private/admin.jwt --profile-id <PROFILE_ID> --service-date <TODAY_MANILA> --lat <LAT> --lng <LNG> --json-out /private/proof.json`. The script registers, challenges/binds, paginates bootstrap to a final sync cursor, pulls, pushes check-in then dependent note activity/check-out, replays the identical operations with fresh HTTP challenges, conflicts a changed payload with the same key, revokes, then uses a previously issued fresh nonce to verify HTTP denial. It prints only redacted counts, statuses and opaque IDs. The batch is **not atomic**: check-in must complete first to obtain the server visit ID for activity/check-out. If there is no planned visit today, it reports `push_skipped_no_planned_visit_today` and still checks bootstrap/pull/revocation; this is not an execution proof. `--allow-no-visit --outlet-id <ID>` explicitly opts into an unplanned visit, but the outlet must belong to the salesperson and policy may keep location evidence pending. A `--service-date` other than Manila today skips writes, never changes the server clock.
5. Independently read back the registered device status, visit, execution events, processed operation rows and mobile changes through authorized DEV tools. Confirm exactly one visit, accepted operation IDs/acks unchanged across HTTP retries, three accepted writes, changed-payload conflict, and revoked device. Test wrong signature, nonce replay and a different bearer on real DEV as an additional security smoke test; Vitest mocks cannot prove JWT propagation. Remove temporary JWT files and retain only the redacted summary. If the CLI fails before revoke, it attempts admin cleanup and reports when manual cleanup is needed.

## Wire protocol

All routes are POST JSON, no mobile CORS. `Authorization: Bearer <Convex JWT>` plus `x-mobile-contract-version: 1`, `x-mobile-device-id`, `x-mobile-app: IOS|ANDROID`, `x-mobile-nonce` (fresh server-issued UUID challenge), `x-mobile-timestamp` (epoch milliseconds), `x-mobile-body-digest` (lowercase SHA-256 hex of exact raw body), `x-mobile-signature` (base64 P1363 ECDSA P-256/SHA-256 signature of `POST|/mobile/v1/<route>|<digest>|<nonce>|<timestamp>`). Body `deviceId` must equal the header. Maximum raw body 128 KiB, bootstrap 1–100 per page, pull 1–50, push 1–20 ordered operations. Version mismatch yields `version_unsupported` (400); missing/invalid bearer or proof yields `unauthorized` (401); oversized/malformed request yields `invalid_request` (413/400); expired/changed projection yields `rebootstrap_required` (409). Unexpected backend failure yields redacted `temporarily_unavailable` (500). Business operation rejections are ordered per-op results. Do not send a Better Auth session token or connector HMAC as the mobile bearer.

Coverage activation/supersession and outlet assignment changes write an invalidation feed entry transactionally; pull either detects a changed signed manifest or returns `rebootstrap_required` on an unsupported changed entity. The execution guard rejects an attempt to cancel/replace a planned visit with any visit execution row, including an in-progress one. Convex rolls back the entire rejected transaction, so there is no durable rejected-attempt audit write inside that same mutation; successful plan transitions retain MCP audit rows. Do not interpret an empty delta as a complete change feed for unsupported sources. `domains/orders.ts` and `inventory/pos.ts` audit hooks are deferred; no mobile order/stock push or SAP integration is promised. Location/media certification and device attestation remain provisional pending security and client policy approval.
