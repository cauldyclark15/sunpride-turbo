# Native field DEV — v1 wire, proofs and offline boundary

**Scope:** iOS `apps/field-ios` and Android `apps/field-android` field clients only. This is an implementation runbook, not native-device DEV acceptance or client approval of offline rules. See [MOBILE_SFA_V1](../contracts/MOBILE_SFA_V1.md), [MOBILE_AUTH_V1](../contracts/MOBILE_AUTH_V1.md), [MOBILE_SFA_V1_COMPATIBILITY](../contracts/MOBILE_SFA_V1_COMPATIBILITY.md), [MOBILE_SYNC_DEV](MOBILE_SYNC_DEV.md), ADR-010/019/020/021 and the canonical JSON Schema. The working **JS** reference is `packages/backend/scripts/mobile_fake_device.ts`; its success is not native-app evidence.

## Origins, sign-in, enrollment and renewal

Set **two distinct HTTPS origins** per DEV build: `CONVEX_SITE_URL=https://<deployment>.convex.site` for Better Auth and `/mobile/v1/{bootstrap,pull,push}`, and `CONVEX_URL=https://<deployment>.convex.cloud` for authenticated Convex function calls. Never use the session token on `.convex.cloud` or the Convex JWT as a Better Auth session token. No native CORS requirement. Validate scheme, distinct matching deployment hosts and nonempty settings at startup/build; no production fallback to DEV.

1. Online, an invited employee POSTs `{"email":"<invited email>","password":"<private password>"}` as JSON to `${CONVEX_SITE_URL}/api/auth/sign-in/email` via URLSession/OkHttp. **Omit `Origin` entirely.** The DEV endpoint was probed with an obviously invalid credential: no `Origin` reached credential evaluation (401); literal `Origin: null` returned 403 `MISSING_OR_NULL_ORIGIN`. This is not a successful real-account sign-in or a proof of production policy. `convex/auth.ts` only lists `WEB_SITE_URL` and `PWA_SITE_URL` as `trustedOrigins`; never forge either as a native workaround. Escalate if the deployed native no-Origin behavior changes. The Better Auth response supplies the user/session shape; specifically read the `set-auth-token` response **header** emitted by its bearer plugin. A 401 is not a session; never parse a token from a failed body. Keep the session token only in Keychain (`ThisDeviceOnly`, after first unlock) or Keystore-protected Android storage, excluded from backup. Do not log, put in argv, commit or embed it in a build. Password is not persisted by the app.
2. Exchange via `GET ${CONVEX_SITE_URL}/api/auth/convex/token` with `Authorization: Bearer <Better Auth session token>`; parse the JSON `token` field. The `convex()` plugin in `convex/auth.ts` registers the route; the resulting `aud=convex` JWT has a default **15-minute** lifetime (see MOBILE_AUTH_V1). Keep it in memory; refresh by repeating this GET using the secure session token before expiry or on an auth failure, then retry only safely replayable requests. If the session is expired/revoked, require online sign-in again. Use `Authorization: Bearer <Convex JWT>` for both cloud function requests and the site mobile HTTP actions. Never send either token in a query string or diagnostic output.
3. There is **no employee self-registration**. A scoped admin with `admin.manage` in the employee unit calls `mobile/devices:register` with `{inventoryTag,allowedApp:"IOS"|"ANDROID",platform:"iOS"|"Android",model,osVersion,appVersion,profileId,publicKey}`. `profileId` is the server profile ID; `publicKey` is base64 of DER SubjectPublicKeyInfo ECDSA P-256 (not PEM text, SEC1 uncompressed point, JWK or PKCS8). The private key never leaves Secure Enclave/Keychain or Android Keystore. Registration returns `{deviceId,status:"active"}`; one active device per profile/tag. Admin and employee must use **their own** separate authenticated bearer identities.
4. The employee calls `mobile/devices:challenge` with `{deviceId}`. It returns `{nonce,expiresAt}`. Sign `BIND|<deviceId>|<credentialId>|<nonce>|<timestamp>` as UTF-8 ECDSA P-256/SHA-256 with the enrolled private key; `proof` is standard base64 of 64-byte IEEE P1363 `r||s`. Then call `mobile/devices:bind` with `{deviceId,credentialId,attestation:{format,keyId?},nonce,timestamp,proof}` and expect `{bindingStatus:"bound"}`. Attestation metadata is **unverified**; do not label it verified MDM/hardware integrity. A new challenge is required per attempt. Binding must happen online and under the employee bearer.
5. Sign out online by POST `${CONVEX_SITE_URL}/api/auth/sign-out` with the Better Auth session bearer (usual JSON body `{}`); regardless of network outcome, discard the in-memory JWT and secure session credential and lock the local cache. If remote invalidation fails, mark it pending and retry through an explicitly approved secure flow; do not claim server revocation. Preserve unsent outbox/evidence for supervised disposition instead of silently deleting the sole copy. Device revocation is a **separate admin** `mobile/devices:revoke({deviceId,reason})` action (enumerated reason code); a revoked device fails fresh challenges/sync. A disconnected device cannot receive revocation immediately.

**Direct Convex function wire (online-only enrollment/challenges, NOT the sync feed):** POST `${CONVEX_URL}/api/mutation` for `register`, `challenge`, `bind`, `revoke`; POST `${CONVEX_URL}/api/query` for read-only scoped queries. Headers `Content-Type: application/json` and `Authorization: Bearer <Convex JWT>`; JSON request exactly `{ "path":"mobile/devices:challenge", "args":{"deviceId":"<opaque ID>"}, "format":"json" }`. Substitute `mobile/devices:register`, `mobile/devices:bind` or `mobile/devices:revoke` and their arguments above. A success response is `{ "status":"success", "value":{...} }`; an error response is `{ "status":"error", "errorMessage":"..." }` (other metadata may be present). Check HTTP status **and** `status`, never treat HTTP 200 alone as success. `ConvexHttpClient(url).setAuth(jwt)` and `api.mobile.devices.*` in `mobile_fake_device.ts` implement this function protocol; the HTTP gateway instead uses site URL and different envelopes. Do not use CLI `--identity` as a live identity proof.

## Request proof for the site gateway

For each POST to `${CONVEX_SITE_URL}/mobile/v1/bootstrap`, `/pull`, or `/push`: serialize the final JSON body **once**, retain those exact UTF-8 bytes, compute SHA-256 over those bytes and encode its digest as **64 lowercase hexadecimal characters**. Acquire a fresh bearer-authenticated `devices.challenge({deviceId})` nonce. Set `timestamp` to a safe integer UTC epoch **milliseconds** near server time. Sign the UTF-8 canonical text (no newline or spaces around separators):

```text
POST|/mobile/v1/<bootstrap|pull|push>|<lowercase sha256 hex of raw body>|<nonce>|<timestamp decimal ms>
```

P-256 ECDSA/SHA-256 signature is base64 of **IEEE P1363 raw r||s (64 bytes)**. iOS CryptoKit `P256.Signing.ECDSASignature.rawRepresentation` is P1363. Android JCA `SHA256withECDSA` emits ASN.1 DER `SEQUENCE(INTEGER r, INTEGER s)`: parse both positive DER integers strictly, strip exactly the DER `0x00` sign pad if present, left-pad each unsigned integer to **32 bytes**, concatenate r and s; reject malformed/negative/oversized/non-minimal DER. Do not send DER directly to WebCrypto. Test both clients against the **TEST-ONLY** frozen fixture `packages/domain-contracts/fixtures/mobile-v1/crypto/request-proof.json` (high-bit sign-pad, short scalar and UTF-8 body). Never enroll its checked-in private JWK on DEV. The one-shot generator under `packages/domain-contracts/scripts/` refuses to overwrite the fixture.

Send `Content-Type: application/json`, `Authorization: Bearer <Convex JWT>`, `x-mobile-contract-version: 1`, `x-mobile-device-id: <deviceId>`, `x-mobile-app: IOS|ANDROID`, `x-mobile-nonce: <challenge nonce>`, `x-mobile-timestamp: <decimal epoch ms>`, `x-mobile-body-digest: <lowercase sha256 hex>`, `x-mobile-signature: <standard base64 P1363>`. Body `deviceId` must match header. No Origin spoofing. `http_handlers.ts` limits raw body to 128 KiB, checks content type/version, digests the actual received body and compares to the supplied digest **before** invoking `device_auth.authorize` with the hardcoded POST/path. `device_auth.ts` imports base64 DER SPKI P-256, canonical-decodes base64, verifies the P1363 signature with WebCrypto, checks ±60 s clock skew and consumes the server-issued UUID nonce transactionally only after successful authorization. Challenge expires after 60 s, is bound to the device and single-use. Authorization also checks current full bearer subject, active profile/assignment/unit, allowed app, bound key and device status before replay. A rejected request must obtain a new nonce before retry. Server time and scope are authoritative. Read `packages/backend/convex/mobile/{device_auth,http_handlers}.ts` for implementation, not the older provisional proof prose.

Gateway bodies are strict v1 JSON envelopes (`type`, `contractVersion:1`, `deviceId`); bootstrap/pull page limits and nullable/omitted distinctions are in the Schema. Pull **requires** `limit` in that schema. Push is 1–20 ordered operations, each with durable UUID/payload. Error `401 unauthorized` covers missing/invalid bearer or proof, `409 rebootstrap_required`/`invalid_cursor` requires a fresh scoped snapshot. Batch push is not atomic; persist individual acks before dequeue and retry unchanged UUID and bytes after uncertain transport failure.

## Visit-only offline authority matrix — engineering draft for #111, **NOT client-approved**

| Data/operation                                                                               | Device while offline                                                                                                                                                                             | Server on reconnect                                                                                                                  | Failure/recovery                                                                                                                           |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Approved plan/slot, assigned outlet, linked customer, route, task, scope, revision and lease | Read last complete authorized scoped snapshot, clearly stale/pending; never edit server projections locally                                                                                      | Owns approval, eligibility, effective ownership, snapshots, revisions and cursor                                                     | Assignment/plan changes or cursor expiry require rebootstrap; stage pages then atomically swap snapshot/cursor **without dropping outbox** |
| Visit check-in, note/activity, check-out intent                                              | Persist immutable client UUID, exact payload bytes, device time and outbox atomically; label **saved/pending**, not accepted; wait for check-in ack's real `visitId` before dependent operations | Validates service day (Asia/Manila), scope, visit state/evidence and idempotency; returns per-op accepted ack, server event IDs/time | Uncertain network result: resend same UUID and payload, fresh request challenge; no silent rewrite or duplicate check-in                   |
| Accepted visit/activity and pull changes                                                     | Cache server projection and durable ack; advance cursor transactionally, including empty filtered pages                                                                                          | Owns accepted/rejected/conflict status, server visit ID, events, productivity/location exception decisions                           | `rejected`/`conflict` are **frozen for supervisor review**, not auto-merged or deleted; preserve original intent and evidence              |
| Location/media and productivity/per diem                                                     | `location:null` may diagnose an unavailable fix, but label pending review; device observations are evidence only                                                                                 | Owns geofence/exception decision and credit; raw evidence is not certification                                                       | No location, mock or stale fix cannot auto-award productive visit/per diem; policy thresholds and lease are provisional                    |
| Orders, collections/payments, product catalog, prices, stock availability/POS                | **Unavailable**: no create/edit/queue/estimate/fallback; do not treat `order_intent` or collection evidence as an order/payment                                                                  | No field-v1 authority/feed for financial operations; product catalog currently empty                                                 | Require separate scoped catalog/policy and versioned contract before enabling; Android van POS is another app                              |

Read lease/cache expiry from bootstrap `appConfig`; fail closed when absent/expired or clock rollback is suspected. Offline authorization cannot guarantee instant revocation; an offline device may retain evidence but the server rejects revoked credentials on reconnect. Current backend 75 m/50 m/60 s location defaults and 24 h lease are **engineering/provisional**, not client-approved constants for native binaries. Owner/security and Sunpride must approve fleet/MDM, lease, location, retained evidence, lost-device recovery, conflict remediation and productive/per-diem rules before pilot. Do **not** close broad #111 on this draft.

## Local setup and DEV configuration (no committed credentials)

From repo root, with free SDKs installed:

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
export JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home'
export ANDROID_HOME="$HOME/Library/Android/sdk"
xcrun simctl list devices available
# Choose an available iPhone 17 Pro UUID; xcodebuild will boot it as needed.
export SIM_ID='<available iPhone 17 Pro UUID>'
"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" --list
# Select an actually available Google APIs API 36 system image, then install it:
"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" 'system-images;android-36;google_apis;arm64-v8a'
"$ANDROID_HOME/cmdline-tools/latest/bin/avdmanager" create avd -n SunprideDev -k 'system-images;android-36;google_apis;arm64-v8a'
"$ANDROID_HOME/emulator/emulator" -avd SunprideDev
# In another shell, confirm an online emulator:
"$ANDROID_HOME/platform-tools/adb" devices
bun run native:ios
bun run native:android
```

Choose the installed ABI instead of `arm64-v8a` where appropriate; SDK image downloads require owner/network approval. The native scripts fail clearly if their platform project has not been integrated. iOS runs `xcodebuild build` then `test` for `FieldIOS-Dev` on `$SIM_ID` or the first available iPhone 17 Pro; Android runs `:app:assembleDevDebug :app:testDevDebugUnitTest`, plus connected instrumentation only when an emulator is online. These scripts are separate from Turbo's root JS/TS gates and do not prove live DEV auth.

Inject DEV site/cloud endpoint URLs with **untracked, per-flavor local build settings** or CI secret configuration (Swift xcconfig local override / Android local properties or environment, according to the platform scaffold); commit only non-secret templates. Keep credentials exclusively in interactive secure sign-in, session in secure OS store, JWT in memory, and disposable smoke-test token files mode 0600 **outside the repo**. Never put passwords, JWTs, session tokens, signing keys or personal GPS in environment files committed to Git, command arguments, Gradle/Xcode logs or screenshots. Verify the native binaries against DEV with disposable invited identities and authorized admin registration separately; the fake device and these vectors only prove the JS wire and crypto format, not native identity propagation or on-device encryption.
